Systemarchitektur

Modulares Design

Evolution: Von Monolith zu Modulen

Mit steigender Komplexität – insbesondere durch die Einführung der drei Spielmodi und der KI – zeigte sich, dass eine Modularisierung signifikante Vorteile für die Stabilität und Wartbarkeit bietet.

Modul Rolle Verantwortung
MAIN.src Controller State Machine, Programmfluss, Initialisierung
GAME_CTRL.src Model / Logic Regelwerk & KI, virtuelles Spielbrett
ROBOT_MOTION.src View / Hardware Physische Bahnplanung und Aktorik
GAME_DATA.dat Database Globale Daten, Konstanten, Zustände

Vorteile der modularen Architektur

1. Kapselung (Separation of Concerns)

Die Trennung von Logik (GAME_CTRL) und Bewegung (ROBOT_MOTION) erlaubt es, Spielregeln zu testen, ohne den Roboter physisch zu bewegen.

2. Vermeidung von Linker-Konflikten

Durch Auslagerung aller gemeinsam genutzten Variablen in GAME_DATA.dat mit PUBLIC werden Zugriffskonflikte vermieden.

3. Wiederverwendbarkeit

ROBOT_MOTION stellt generische Funktionen bereit, die von allen drei Spielmodi genutzt werden.

KI-Algorithmus

4-Stufen Entscheidungsbaum

Stufe 1: GEWINN-CHECK

Simuliere eigenen Stein in Spalten 1–6. Bei 4er-Reihe → Sofortiger Gewinn!

Stufe 2: BLOCK-CHECK

Simuliere Gegner-Stein in Spalten 1–6. Bei 4er-Reihe → Blockieren!

Stufe 3: STRATEGIE

Bevorzuge Zentrum (Spalte 3 oder 4) für bessere Kombinationsmöglichkeiten

Stufe 4: ZUFALL

Wähle erste freie Spalte von links nach rechts

Abb. 2: KRL Code Implementation

Technischer Exkurs: Das "Status & Turn" Problem

Kinematik Challenge

Das Problem

Eine KRL-Koordinate vom Typ E6POS enthält neben kartesischen Koordinaten (X, Y, Z) auch Achskonfigurationsdaten:

  • Status: Informationen über die Lage des TCP (z.B. Überkopfbereich)
  • Turn: Vorzeichen der Achswinkel (z.B. Achse 4 bei +10° oder -350°)

Bei rein mathematischer Berechnung bleiben S und T erhalten → "Position unerreichbar"

Die Lösung: Der "Frame-Trick"

Impliziter Cast auf FRAME entfernt S/T:

DECL E6POS pTarget
DECL FRAME fMove

; 1. Zielpunkt holen
pTarget = P_FIELD[row,col]

; 2. Cast entfernt S und T
fMove = pTarget 

; 3. Neuberechnung
PTP fMove

Bewegungsablauf

PERFORM_GAME_MOVE Sequenz

Physische Ausführung

  1. Berechne Lagerplatz
    Bestimme Next Stack Position
  2. Anfahrt Vorhöhe Lager
    Kollisionsvermeidung
  3. Greifen & Rausziehen
    Greifer ZU + Vertikale Bewegung
  4. Berechne Ziel
    P_FIELD[row, col]
  5. Frame-Trick anwenden
    fMove = pTarget
  6. PTP über Ziel
    Sicherheitshöhe
  7. LIN zum Ziel
    Präzise Platzierung
  8. Greifer AUF
    Stein freigeben
  9. LIN Rückzug
    Zurück zur Sicherheitshöhe
